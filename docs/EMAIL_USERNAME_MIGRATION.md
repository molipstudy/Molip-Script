# 이메일 로그인·유저네임·회원정보 전환

2026-11-17 사용자가 운영 SQL 실행 완료를 확인했습니다. 저장소의 기존 마이그레이션과 로컬 PostgreSQL 테스트로 검증했으며, 이번 작업에서는 운영 DB 구조를 직접 조회하거나 변경하지 않았습니다.

## 최종 구조

- `auth.users.id` ↔ `molip_profiles.profiles.id`: 동일 UUID·기존 외래키 유지.
- 이메일·비밀번호·세션은 Supabase Auth의 정식 API를 사용합니다. 프로필 테이블에 이메일·비밀번호를 복제하지 않습니다.
- `profiles.username`: 공개 유저네임. 기존 `login_id` 값을 일괄 이전하며, 예전 이메일 앞자리 표시 이름을 덮어씁니다. 기존 아이디 없는 회원은 유효한 기존 username을 유지합니다. 충돌·유효하지 않은 값은 전체 마이그레이션을 중단합니다.
- `profiles.full_name`, `profiles.phone_number`: 비공개 이름·전화번호. 기존 회원은 NULL로 시작하며 이메일·메타데이터에서 실명을 추정하지 않습니다.
- 물리 `login_id` 칼럼과 익명 이메일 검색 함수 `email_for_login_id`는 제거합니다. 기존 API의 `login_id` 응답 필드만 호환 별칭으로 남기며 username을 반환합니다.
- 유저네임은 NFC 정규화·영문 소문자화, 2~32자, 한글/영문/숫자/점/밑줄/하이픈. 첫 글자는 한글/영문/숫자. 고유성은 DB에서 보장합니다.

## 편집·노출

회원은 `my_profile`/`update_my_profile` RPC로 본인의 정보만 조회·편집합니다. 대상 UUID·이메일·관리자 권한을 인자로 받을 수 없습니다. 개인정보를 한 테이블에 저장하되 직접 SELECT·UPDATE 권한은 주지 않습니다. 커뮤니티·단어장 공개 작성자 API는 username 등 기존 공개 필드만 반환하며 실명·전화번호는 반환하지 않습니다. 관리자 상세의 실명·전화번호는 전역 관리자에게만 반환합니다.

유저네임 변경 시 공개 스크립트에 보관된 작성자 유저네임도 소유자 UUID 기준으로 갱신합니다. 댓글·게시자 조회는 항상 공용 username을 사용합니다. UUID를 사용한 서재·학습·별표·취약 단어·팔로우 관계는 변경하지 않습니다.

전화번호는 연락처 문자열입니다. 국내 `01012345678`은 `+821012345678`로 정규화하고 국제 번호는 +국가번호를 사용합니다. SMS 인증·Auth 전화번호 로그인은 추가하지 않으며 입력만으로 인증된 번호라고 표시하지 않습니다.

## 기존 Auth 메타데이터

`auth.users.raw_user_meta_data`의 예전 username/login_id 값은 자동으로 바뀌지 않습니다. 이 SQL은 Auth 데이터·칼럼·트리거 정의를 직접 변경하지 않습니다. 기존 가입 트리거가 호출하는 애플리케이션 소유 `public.handle_new_user()`의 본문만 갱신합니다. UI·권한·프로필의 원본은 공용 테이블입니다. 프런트엔드는 공용 프로필을 읽은 뒤 React 내부의 표시 캐시만 갱신하며 옛 메타데이터를 프로필에 다시 쓰지 않습니다. 역할은 항상 `admin_grants`로 확인합니다.

## 적용 순서

1. 현재 프로필 및 스키마 백업을 보관합니다. 이메일 앞자리였던 기존 username은 승인한 일괄 변환에 따라 기존 login_id로 교체됩니다.
2. `sql/accounts/email-username-upgrade.sql`을 Supabase SQL Editor에서 실행합니다. 충돌이나 예상하지 못한 칼럼 의존성이 있으면 전체 롤백됩니다. 기존 `molip-profiles-finalize.sql`까지 완료된 구조를 전제로 합니다.
3. 이 변경 코드를 배포합니다. SQL이 기존 아이디 조회 함수를 제거하므로 로그인 전환 작업은 같은 유지보수 시간에 진행하세요. 오래 열린 탭·PWA는 새로고침해야 합니다.
4. 기존 회원 이메일 로그인, 한글 유저네임 신규 가입·인증 이메일, 내 정보 편집, 커뮤니티 작성자명, 단어장 계정 API, 관리자 상세를 확인합니다.

새 화면은 아이디 로그인을 지원하지 않습니다. 로그인 화면에 변경 안내를 유지하고 이메일에 `autocomplete=username`, 비밀번호에 `current-password`를 지정합니다. 저장된 이전 아이디가 자동 입력되면 이메일로 바꾸도록 안내합니다.

이름·전화번호 미입력 회원은 접속 시 안내 배너를 봅니다. ‘나중에’는 현재 앱 실행 동안만 숨기며 새 접속에는 다시 표시됩니다. 학습 화면은 방해하지 않고 내 정보 화면에는 미입력 상태·편집 버튼을 계속 표시합니다. 정보가 실제 저장되면 안내는 사라집니다. 신규 회원도 가입 후 내 정보에서 입력할 수 있습니다.

## 운영 확인용 SELECT

```sql
select count(*) as profiles,
       count(*) filter (where full_name is null) as missing_names,
       count(*) filter (where phone_number is null) as missing_phones
from molip_profiles.profiles;
```

개별 연락처를 일반 공개 API나 공개 로그로 출력하지 않습니다. 이 단계에는 Auth 메타데이터 일괄 정리나 실명·전화번호 자동 추정이 포함되지 않습니다.
